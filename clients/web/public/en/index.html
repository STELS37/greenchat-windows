Privacy and device security

Concrete controls instead of vague promises

Green Chat does not require a phone number and provides explicit tools to protect local data. You decide which protections to enable.

01

Local application lock

Protect access with a code or passphrase. On supported devices, biometrics can be used as a convenient unlock method.

02

Encrypted local cache

After the lock is enabled, local message and media cache is migrated into encrypted device storage.

03

Emergency code

An optional separate code clears local data and the device session. Server-side actions are best-effort when connectivity is available.

Lock enabledLocal data is protectedThe key remains on the device

We avoid absolute security language and state the boundaries of device protection. This page lists actual capabilities and limitations.

Product principles

User freedom is a foundation, not an add-on

01

No forced identity binding

A unique @username and password are enough to register. Phone and email are not published in the profile.

02

No hidden telemetry

Diagnostics require user consent; the public site uses no external trackers or advertising SDKs.

03

No pretend availability

Beta status, platform availability and limitations are stated directly. Missing native builds are not replaced with fake download buttons.

FAQ

The essentials, answered

This page lists only features that are already available in the public beta.

Is a phone number required?

No. A unique @username and password are used for registration. Phone and email are optional.

Can I use Green Chat without installing anything?

Yes. The web version works in a modern browser and can be installed as a PWA on supported devices.

What happens when the network drops?

Pending outgoing actions remain in the local queue. When connectivity returns, the client continues sending and restores missed events.

Are native iPhone, Windows and macOS apps available?

A native x86_64 beta installer is published for Windows. iPhone, iPad and macOS currently use the web/PWA version; each platform card shows the current status.

How do I report a problem?

After signing in, open the built-in support screen. A report can wait in the local queue and be sent when connectivity returns.
